## Cutover state machine

The release transaction is monotonic:

`baseline-five-rollback`

-> `candidate-1/rollback-4`

-> `candidate-2/rollback-3`

-> `candidate-3/rollback-2`

-> `candidate-4/rollback-1`

-> `candidate-live-5/0`

-> `first-journey-passed`

-> `second-journey-passed`

-> `final-accepted`

Any mismatch before `final-accepted` enters `all-five-rollback`. No path pauses with a partial mapping for unrelated diagnosis.

## Cutover and rollback

Cutover uses five explicit assignments to the existing candidate immutable URL in legacy-team, team-project, project, `www`, apex order. Every step rereads all five and must produce the exact candidate/rollback counts.

Rollback uses five explicit assignments to the rollback immutable URL in apex, `www`, project, team-project, legacy-team order. Assign all five even if some appear safe. Every step rereads all five; final recovery is five/five Ready rollback plus route safety.

The planned explicit alias mechanism is intentionally narrower than a project-wide promote or platform rollback because this project has an exact five-alias affected set and prior deployment-level metadata ambiguity. Current official documentation and installed help must still confirm the mechanism immediately before mutation.

## Failure and recovery

- Wrong canonical/remote baseline or unexpected handoff diff: stop before branch/external action.
- Wrapper/core hash or closed-allowlist mismatch: correct only inside the two approved tooling files and revalidate.
- Existing service-role access unavailable: record exact private manual intervention if the existing authorized value can be entered safely; do not create/rotate a credential. If still unavailable, close retained-pilot preflight mismatch before Vercel mutation.
- Retained-pilot mismatch: no repair; close before Vercel.
- Product bytes differ or source change is required: close existing-candidate preflight blocked before Vercel.
- Existing candidate or rollback not exact/Ready: no deploy and no alias mutation; close preflight blocked.
- Baseline not five/five rollback: restore all five to rollback when exact safe authority exists; otherwise stop partial-mutation blocked.
- Candidate immutable smoke fails: no alias mutation.
- Cutover snapshot mismatch: immediate all-five rollback.
- Canonical route or material auth/privacy/integrity failure: immediate all-five rollback.
- Human transient/input/cooldown classification: one sanitized diagnosis and at most one cooldown-safe non-blind retry; otherwise rollback.
- Source/provider/configuration/schema/permission/identity/fixture/data change required: rollback and close source-or-contract-change-required.
- Final rollback cannot be proven: stop partial-mutation blocked with exact manual intervention.
