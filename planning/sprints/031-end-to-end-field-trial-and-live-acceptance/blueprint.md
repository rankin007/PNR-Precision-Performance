# Sprint 031 Blueprint

## Phase 1 — Freeze source and reconcile prerequisites

1. Record exact worktree, branch, HEAD and complete dirty manifest.
2. Fingerprint all pre-existing Sprint 025–030 changes and freeze migrations/lockfile/reference files.
3. Reconcile closeout outcomes and intentional unavailable boundaries.
4. Inventory current routes, actions, permissions, Supabase/Storage contracts and maintained proof.
5. Create the approved changed-path and external-mutation manifest.

## Phase 2 — Design the governed trial

1. Create `docs/END_TO_END_FIELD_TRIAL_AND_LIVE_ACCEPTANCE_031.md`.
2. Define actors, synthetic horses/stable, exact matrix cases, viewports/devices and timings.
3. Declare run ID, creation ceilings, ownership ledger, zero-state queries, cleanup order and stop rules.
4. Map each case to executable rendered/runtime proof or an explicitly justified equivalent.
5. Define one primary happy-path chain from sign-in through dashboard, horse workspace, capture/review/submit, result/history and evidence action.
6. Define denial, revocation, unavailable, accessibility and recovery slices independently.

## Phase 3 — Build local proof and correct in-contract defects

1. Run the full canonical local suite and production build before external work.
2. Add only the fixture/harness capabilities missing for the matrix; keep secret output impossible by construction.
3. Run credential-free harness self-tests, output allowlist tests, ceiling/ownership tests and cleanup simulations.
4. Perform local rendered smoke across required viewports.
5. Correct only deterministic in-contract product or harness defects, then rerun focused regressions.
6. Scan source/evidence for secrets, personal data, real horse/stable names and unsafe claims.

## Phase 4 — Prove exact Preview target

1. Confirm the exact Vercel project and generated Preview environment; refuse custom Production aliases.
2. Confirm the exact approved Singapore Supabase project and ledger `0001`–`0021` using protected/non-secret methods.
3. Confirm only approved Preview environment bindings by configured/missing status, never values.
4. Confirm initial exact-owned Auth/application/Storage zero and no prior run-ID anchors.
5. Deploy the validated Sprint 031 candidate to a new generated Preview if required.
6. Run anonymous route/safety smoke before creating fixtures.

## Phase 5 — Execute bounded authenticated matrix

1. Create exact-owned synthetic identities and fixtures within ceilings.
2. Run authentication/access lifecycle cases.
3. Run the primary mobile trainer chain and desktop review chain.
4. Run results/history/trend and dashboard/workspace cases.
5. Run one integrated rendered evidence action chain and reuse stronger equivalent Sprint 023L proof only where valid.
6. Prove unavailable clinical, priority, audio and commerce boundaries.
7. Run denial, revocation, accessibility, slow/error and recovery cases.
8. Stop at the first material integrity/security/privacy failure; compensate partial creation immediately.

## Phase 6 — Correct and reprove proportionately

1. Classify each failure as product defect, harness/tooling defect, authority boundary, environment limitation or external blocker.
2. Correct in-contract product/harness defects within the approved files.
3. Redeploy only when the changed runtime candidate requires it.
4. Rerun focused local gates and only affected remote/rendered slices plus shared cleanup controls.
5. Do not turn unavailable authority into fixture-backed behaviour.

## Phase 7 — Cleanup and final accounting

1. Remove exact-owned evidence objects through governed paths.
2. Remove application fixtures dependency-safely.
3. Remove/revoke sessions and Auth identities last.
4. Prove final Auth/application/Storage owned counts `0/0/0`, no run anchors and no recovery orphans.
5. Confirm ledger, Production aliases/environment, Stripe state and non-owned data are unchanged.
6. Clear protected processes/browser contexts and temporary secret material.

## Phase 8 — Acceptance recommendation and closeout

1. Reconcile every matrix row with evidence class and result.
2. Record observed timings without unsupported speed claims.
3. Separate passed capability, accepted limitation, residual risk and launch blocker.
4. Issue one recommendation: proceed to Production release planning, proceed with named limitations, or no-go pending material correction/authority.
5. Run final canonical validation/build/diff/path/privacy/secret scans.
6. Refresh state, status, decisions, risks, questions, schedule/list, evidence index and Architect briefing.
7. Leave source unstaged/uncommitted and do not push, merge or open a PR.

## Stop conditions

Stop and clean owned state when:

- exact source, Vercel Preview, Supabase project/region or migration ledger differs;
- a Production alias/environment or Stripe/payment path would be touched;
- secrets or unexpected protected/real data appear;
- creation ceilings or ownership accounting are exceeded;
- wrong-horse/cross-stable denial, signature/safety, RLS, integrity or revocation fails;
- a migration/schema/RLS/permission/new-authority change is required;
- cleanup cannot restore and prove exact owned zero.
