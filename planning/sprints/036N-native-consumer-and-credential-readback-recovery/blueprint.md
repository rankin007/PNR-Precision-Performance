# Sprint 036N Blueprint - Native Consumer and Credential Readback Recovery

## Build Sequence

1. Reconfirm canonical workspace, accepted dirty tree, zero staged/conflicts, Sprint 036M blocked-clean baseline, accepted Sprint 036L source, fixed five aliases, three binding classes, migration authority, and unchanged lockfile.
2. Derive the exact repository consumer manifest for the seven credential classes and bind it to source hashes.
3. Build finite provider adapters and paginated inventory projections for Vercel, Supabase, SMTP provider, Stripe, and Railway. Unknown providers or unbounded output fail closed.
4. Add pure transaction, disposition, deletion-allowlist, irreversible-latch, compensation, privacy, and residue controllers with adversarial focused tests.
5. Run sanitized capability discovery. Stop clean before mutation if exact account/project authority, pagination, provider lifecycle, or predecessor rejection cannot be proved.
6. Prepare exact-source primary and rollback deployments; prove Ready, source identity, alias state, current-key compatibility, and zero business effects.
7. Move the fixed five aliases only after both deployments pass and independently reread all aliases.
8. Execute class transactions independently. A class may remain blocked-retained without converting another class to success.
9. Retire only the frozen exact-ID set of predecessor-bearing deployments after both replacements and class readbacks protect rollback.
10. Perform full provider/source/alias/binding/disposition/residue reread, rerun local gates, request same-Architect diff review, then close out truthfully.

No Product compatibility file may be added without a discriminating red test and a reviewed plan correction.

## Consumer Manifest

The source-derived manifest must cover:

- Vercel Production, Preview, and Development bindings for the three binding classes
- every current and still-addressable deployment
- `vercel.json` Cron definitions
- internal enquiry routes and callers
- Supabase Edge Functions
- database webhooks and `pg_net`
- SMTP, Stripe, and Railway source consumers
- externally configured provider callbacks or jobs discoverable through exact provider inventory

Provider inventory is compared with the source manifest. Missing, extra, duplicate, unowned, unpaginated, or unknown consumers block before mutation.

## Primary and Rollback Deployments

Both deployments must:

- originate from the exact accepted Sprint 036L Git object, never the dirty canonical tree
- use an exact-owned ephemeral export or an equivalently reviewed exact-source provider mechanism
- match the exact Vercel team/project
- reach Ready
- remain free of automatic alias ambiguity before the fixed alias transaction
- pass public, authenticated-user, and server-admin no-business probes under the replacement bindings
- be independently addressable for rollback

The primary receives the five aliases. The rollback remains unaliased but Ready and current-key compatible.

## Deployment Retirement

Freeze an exact deletion allowlist from complete paginated inventory. Before each delete, re-read:

- exact deployment ID
- team/project
- source identity
- current alias membership
- primary/rollback exclusion
- predecessor-binding relevance
- deletion reason

Delete only exact predecessor-bearing deployments after both replacements and all required current readbacks pass. After deletion, paginate again and prove each ID absent. Any uncertain deployment is retained and blocks full target closure.

## Credential Transactions

Each class is a separate finite state machine:

`baseline -> replacement-prepared -> installed -> probed -> predecessor-attempted -> independently-read -> terminal`

Predecessor-attempted is latched before the provider call. After that state, compensation cannot restore the predecessor.

### Supabase

Use exact-project Management API/native authority for modern secret-key lifecycle and legacy-key status. Prove current admin behavior with the new secret and predecessor rejection without changing JWT signing, public anon, or user sessions.

### Cron and HMAC

Inventory every caller and route. Prove all current consumers accept the replacement and every addressable old consumer rejects or cannot access the predecessor.

### SMTP

Use provider-native key inventory/create/revoke/readback and authentication-only verification. Never send email.

### Stripe

Use provider-native secret-key and webhook-secret lifecycle. Keep commerce disabled and invoke no payment or webhook business event. Dashboard-only rotation is allowed only with independent API authentication rejection or exact provider readback.

### Railway

Use exact account/project token lifecycle and harmless metadata authentication. Vercel absence, repository text, or operator confirmation is not a revocation oracle.

## Discriminating Tests

Tests must falsify at least:

- omitted second or later pagination page
- duplicate or cross-project deployment
- accepted source mismatch
- primary or rollback automatically aliased or not Ready
- one fixed alias left on the predecessor
- old deployment still accepting the predecessor after claimed closure
- Vercel env absence while a provider token remains valid
- SMTP authentication passes while the predecessor key remains listed
- Stripe predecessor endpoint/key remains enabled
- Railway predecessor token still authenticates
- mutate-then-throw, timeout, or ambiguous provider response
- post-attempt compensation trying to restore a predecessor
- deletion allowlist containing primary, rollback, current aliased, foreign, or unknown deployment
- raw protected value in output/evidence
- fallback incorrectly reported as launch or trainer readiness

## Landing Rules

- Complete target: all seven exact terminal dispositions satisfy authority, all predecessor-bearing deployments are absent or provably incapable, primary and rollback are current-key compatible, aliases/bindings/source are exact, and residue is zero.
- Blocked-clean: no unsafe mutation occurred or every reversible owned mutation was compensated and independently reread.
- Compensated-clean: bounded pre-irreversible mutations occurred, all were exactly restored/removed, and accepted Sprint 036L remains intact.
- Blocked-material: an irreversible attempt or ambiguous external state cannot be safely classified; stop all further mutation and preserve exact readback evidence.
