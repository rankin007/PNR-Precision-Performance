# Builder Handoff - Sprint 034F Repository and Method Integration

**objective:** Establish a coherent, fail-closed repository/method layer on the exact current-main branch with no Product, database, provider, Production or publication change.

**owns:** The exact method/launcher/template/importer/updater allowlist; canonical `AGENTS.md`; the current root `architect-chat-starter-prompt.md`; semantic `.gitignore`; one focused 034F test; and minimum current-only planning/docs records enumerated by the sprint requirements.

**must_not:** Touch Product/runtime/database/dependency/deployment surfaces; import historical planning/evidence; inspect the excluded DOCX or unrelated untracked content; access providers or credentials; stage unrelated files; commit, push, open a PR, merge, rebase or change any remote ref.

**acceptance:** AC-01 through AC-15 in `acceptance.md` pass with real output, exact invariance, independent cross-layer diff review and complete current-only closeout.

**verification:** Run the canonical/branch checks, three Node syntax checks, focused method test, JSON validation, manifest/hash and ignore/scope assertions, `git diff --check`, exact status/scope proof, independent diff review and final closeout reread.

## Builder instructions

1. Recheck canonical cwd/Git root, branch, base and unrelated untracked exclusions before implementation.
2. Work only from the applied sprint files and exact source Git objects; do not cherry-pick or replay historical commits wholesale.
3. Preserve unrelated work and stop for any unexpected collision with an owned path.
4. Use the Evidence-Proportional Execution Standard in `requirements.md`; diagnose once and use an equivalent or stronger safe proof when a supporting tool fails.
5. Keep deterministic importer, updater, validator, formatting, encoding, reporter and test corrections inside 034F when they do not change the approved outcome.
6. If manual intervention becomes genuinely necessary, record the blocker, evidence checked, exact step-by-step action and what will be verified afterward.
7. Do not commit or publish. Finish only after independent review passes and all current-only closeout records are reread from disk.
