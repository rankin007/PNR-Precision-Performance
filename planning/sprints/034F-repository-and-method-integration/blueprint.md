- Recheck canonical cwd/Git root and exact branch/base before every mutation phase.

### 3. Merge repository hygiene semantically

- Preserve every current-main ignore rule unless a concrete conflict requires correction.
- Add applicable `.validation-logs`, `.logs`, Supabase temp/branch, desktop and legacy release exclusions.
- Ignore unrelated `.claude` content while explicitly unignoring only the exact tracked method command files.
- Do not add an ignore rule for the excluded DOCX and do not inspect its content.

### 4. Prove behavior

- Add one dependency-free Node test covering Pack dry-run/application isolation, traversal/protected-target refusal, updater import without network, same-version local-correction retention, manifest/content-hash agreement, coherent class-scaled launch authority, safe direct-root behavior and unsafe-path/workspace refusal.

- Do not rerun a Product build or Product suites because this slice cannot reach Product/runtime/package content.

### 5. Close proportionally

- Have an independent Architect context inspect the full diff and real check evidence against every acceptance criterion.
- After pass, mark only 034F done, refresh current-only state/briefing/review/status and reread all closeout files and the final diff.
- Leave publication and later slices planned, not implied.

## Flight evidence

1. **Class and reason:** `cross-layer`; the authority flows through manifest, updater, templates, launchers, repository guard and executable validation, while no critical Product/auth/data/payment/Production or irreversible external action is included.
2. **Acceptance invariant at risk:** current `main` gains a self-consistent, fail-closed method layer without any Product/runtime/database/dependency change or historical evidence being mistaken for integration.
3. **Affected layers and verified paths/symbols:** manifest file allowlist and SHA-256 values; `update-method.js` path/mode/placement functions; Architect/Builder/Fly launcher bodies; `AGENTS.md` canonical guard; Pack importer path validation; focused test and current-only planning sinks.
4. **Source, transformations and sink:** the accepted 29-entry continuity manifest is the base. Final classification is 17 unchanged Git blobs, six Git-derived local transformations, four unchanged manifest-bound source-absent Claude launchers, and two transformed source-absent Claude launchers. The manifest records the exact eight-file v18 transformation delta in `localCorrections`; semantic `.gitignore`/current-planning adaptation completes the transformation; the fresh current-main branch and its executable method/test surface are the sink.
5. **Discriminating examples:** a valid relative sprint path is reported/applied inside the project while `../outside` and protected `.gitignore` targets fail; a valid direct-root method set passes manifest hashes while an omitted/changed method file fails; exact method command paths remain visible while unrelated `.claude` content stays ignored.
6. **Durable verification source:** exact base SHA, continuity Git object IDs/content hashes, final Git diff and actual command output.
7. **Known uncertainty:** the discovery-stage stale-test concern exists only on the continuity lineage; current `main` contains no such test. The sprint therefore creates one focused current-interface test and records that correction rather than importing stale machinery.
