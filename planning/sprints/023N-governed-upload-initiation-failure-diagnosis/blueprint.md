# Sprint 023N - Governed Upload Initiation Failure Diagnosis Blueprint

## Phase 1 - Preserve And Reconcile

1. Verify the exact continuation baseline, linked target, ledger, structural proof, zero state and approved 023L delta.
2. Apply/verify all four 023N sprint files without changing existing 023L evidence.
3. Record hashes of immutable migrations and relevant committed source.

## Phase 2 - Static Contract Comparison

Compare the repository call site, repository adapter and migration `0019` function declaration parameter-by-parameter. Record only names/types/nullability/default/return-shape agreement. Inspect error translation to determine what conditions collapse to `INITIATION_FAILED`.

If an exact static mismatch fully proves the cause, do not create remote fixtures. Complete cleanup verification and close with a source-contract classification.

## Phase 3 - Read-Only Hosted Metadata

If static evidence is insufficient, run one bounded read-only catalog batch proving function signature, execute grants, security mode, configured search path and dependent object presence. Use one aggregate result. Stop on target/ledger drift or unexpected metadata.

## Phase 4 - One Governed Reproduction

If still required:

1. Reconfirm remote `0/0/0` and empty recovery directory.
2. Create exact owned synthetic Auth user, application user, active role/membership, stable, horse and test using the established protected scoped harness.
3. Verify prerequisite authority as Booleans/counts only.
4. Invoke governed initiation once using a valid small JPEG declaration, acknowledgement `true`, unique idempotency key and `replacesId = null`.
5. Do not transfer bytes regardless of result.
6. Capture only sanitised error class/SQLSTATE, safe stage classification and exact-owned audit/count result.
7. Do not retry.

## Phase 5 - Classify And Clean

Classify one of:

- `application-rpc-contract-mismatch`;
- `database-function-resolution-or-grant-defect`;
- `authenticated-authority-context-defect`;
- `validation-or-idempotency-contract-defect`;
- `constraint-audit-or-return-shape-defect`;
- `error-translation-obscures-valid-denial`;
- `environment-or-cache-classification`;
- `not-reproduced-with-governed-valid-fixture`; or
- `unresolved-safe-diagnostic-boundary`.

Perform exact cleanup with Auth last and verify `0/0/0/0`. Delete ephemeral harness artifacts. Run JSON, approved-path, secret/privacy-pattern and `git diff --check` validation.

## Phase 6 - Stop For Architect

Successful diagnostic outcome is `governed-initiation-failure-classified-clean`. It means root cause is evidenced and cleanup passed; it does not mean corrected.

Recommend, but do not implement:

- an application/source corrective sprint if the committed call or error translation is defective;
- an additive migration `0020` sprint if applied database logic/grants/signature require correction; or
- a 023L proof resumption only if the valid governed call succeeds without correction and the earlier failure is safely explained.

Do not stage or commit without a separate instruction.
