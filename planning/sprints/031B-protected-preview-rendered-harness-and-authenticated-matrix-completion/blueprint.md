# Sprint 031B Blueprint

## Phase 1 — Freeze and reconcile

1. Record exact worktree, branch, HEAD, dirty manifest and Sprint 031 outcome.
2. Fingerprint all pre-existing Sprint 025–031 paths; freeze migrations, lockfile and references.
3. Verify exact Preview, Singapore Supabase project, ledger `0001`–`0021` and run-owned `0/0/0`.
4. Reconcile the precise Sprint 031 transport failure and reject unchanged failed methods.
5. Inventory current auth-cookie/session format and verified historical genuine-cookie harness sources.
6. Declare approved paths, external actions, run ID, ceilings and cleanup plan.

## Phase 2 — Select and design transport

1. Choose the smallest supported browser/driver route that can provide isolated rendered contexts and genuine cookies.
2. Document session acquisition, app-cookie serialization, Preview-origin installation and server agreement without recording protected values.
3. Reuse verified historical algorithms where compatible; adapt target/origin/session shape explicitly.
4. Build output allowlisting and redaction as a hard failure boundary, not post-processing.
5. Define process ownership, timeouts, cancellation and cleanup for browser, driver and helpers.
6. Preserve application auth/RLS behavior; add no bypass/debug route.

## Phase 3 — Credential-free executable transport proof

Prove before remote fixtures:

- browser launch/page control;
- Preview-origin isolation;
- synthetic placeholder cookie shape and server receipt;
- three isolated actor contexts;
- simulated revocation transition;
- token/cookie/email/password/OTP/link output rejection;
- fixed-class/count-only reporter;
- timeout and exact process cleanup;
- no source secret or persistent protected file.

Run focused self-tests repeatedly enough to establish deterministic cleanup, not to mask failures. Diagnose once and switch safely if the chosen mechanism cannot meet the contract.

## Phase 4 — Local and target gates

1. Run maintained Sprint 031 controls and full canonical local validation/build.
2. Run local rendered anonymous/responsive smoke with the selected browser route.
3. Reverify exact non-Production Preview and approved Preview bindings by name/presence only.
4. Reverify exact Supabase target/region/ledger and initial exact-owned zero.
5. Deploy a corrected candidate only if source/runtime changed.
6. Confirm no Production alias, Stripe path or non-owned fixture is in scope.

## Phase 5 — Minimal protected bootstrap gate

1. Create the minimum exact-owned synthetic identity needed for one writer bootstrap.
2. Acquire its session through the supported protected method.
3. Install the genuine app-compatible session into one isolated Preview browser context.
4. Prove rendered `/portal` identity/session agreement and one authorized horse-bound read after minimal fixture creation.
5. Revoke/clear and prove rendered denial.
6. If this gate fails, compensate all owned state and stop before the full matrix.

No protected output may appear. A passed bootstrap gate is required before creating the remaining actors/fixtures.

## Phase 6 — Execute frozen matrix

1. Create remaining exact-owned actors and fixtures within ceilings.
2. Run all 25 cases unchanged, recording rendered/runtime assertions and sanitised classifications.
3. Stop at the first material security/privacy/RLS/integrity failure and compensate immediately.
4. Correct in-contract defects only; rerun affected cases plus transport, denial and cleanup controls.
5. Do not substitute historical/static evidence for cases the rendered harness can now execute.

## Phase 7 — Cleanup and independent final proof

1. Remove evidence/Storage objects through governed paths.
2. Remove application data dependency-safely.
3. Revoke/clear sessions and delete Auth identities last.
4. Run the primary exact-owned zero verifier.
5. Run an independent final verifier/process check proving Auth/application/Storage `0/0/0`, no run anchors/recovery orphans and no owned browser/driver/helper process.
6. Confirm migrations, lockfile, Production/Vercel aliases, Stripe and non-owned remote state are unchanged.
7. Clear protected browser contexts, memory and temporary files.

## Phase 8 — Closeout

1. Update the existing Sprint 031 matrix with 031B rendered results; preserve the original blocked record as history.
2. Create `planning/reviews/031B-protected-rendered-transport-results.md`.
3. Create `planning/reviews/031B-authenticated-matrix-and-cleanup-closeout.md`.
4. Record passed capabilities, accepted limitations, residual risk and Production release recommendation.
5. Run final canonical validation/build/diff/path/secret/private-data/artifact scans.
6. Refresh state, status, decisions, risks, questions, schedule/list, evidence index and Architect briefing.
7. Leave all work unstaged/uncommitted.

- New 031B transport/redaction/isolation/process self-tests.
- Maintained Sprint 031 10-control/25-case contract.
- Relevant Sprint 021 genuine-cookie/auth/RLS/browser regressions.
- Sprints 022/025–030 product and unavailable-boundary regressions.
- JSON, domain, roles, Supabase self, static and encoding.
- TypeScript, cache-independent ESLint and production build.
- Authenticated rendered Preview 25-case matrix.
- Primary and independent final `0/0/0` plus process cleanup.
- `git diff --check`, approved-path, migration/lockfile identity and secret/private-data/claim/artifact scans.

## Stop conditions

Stop and clean owned state if:

- source, Preview, Supabase project/region or ledger differs;
- protected values reach output, disk, arguments, screenshot, clipboard or conversation;
- genuine server-compatible session agreement cannot be proven;
- browser contexts are not isolated or owned processes cannot be terminated;
- ceilings/ownership are exceeded;
- wrong-horse/cross-stable denial, revocation, RLS, evidence safety or integrity fails;
- schema/RLS/permission/dependency/new-authority change is required;
- Production/Stripe/non-owned state would be touched;
- exact cleanup cannot be proven.
