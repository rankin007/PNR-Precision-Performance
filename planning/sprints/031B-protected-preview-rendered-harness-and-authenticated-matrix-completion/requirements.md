## Protected rendered transport contract

### Required behavior

The selected harness must:

- use a mature installed browser/driver or an equivalent supported rendered browser surface;
- create a genuine app-compatible authenticated session for each exact-owned synthetic actor;
- install that session into an isolated browser context for the exact Preview origin before protected navigation;
- use the same cookie/storage/session contract the application ordinarily consumes;
- prove browser-to-server identity agreement through rendered protected behavior, not token inspection;
- isolate actor contexts and prevent cookie/session reuse across roles;
- support revocation and prove the rendered session loses access;
- terminate all owned browser/driver/helper processes deterministically;
- emit only fixed-class results, allowlisted synthetic aliases and aggregate counts.

The harness must not:

- print, log, persist, screenshot, return or expose access/refresh tokens, cookies, passwords, OTPs, magic links, mailbox identifiers, credentials or secret fragments;
- pass protected values through command arguments, environment dumps, clipboard instructions, durable `.env` files, browser-visible debug pages or conversation;
- use localStorage-only injection when the server-rendered application requires genuine cookies;
- add an application test bypass, debug login, backdoor route, weakened middleware or persistent test-only production code;
- reuse a Production user/session, real mailbox/person or prior run identity;
- rely on an installed browser extension or signed-in personal browser profile.

### Transport proof before fixtures

Before any remote identity or application fixture creation, the harness must pass credential-free controls proving:

- browser/driver launch and page-level control;
- exact Preview-origin context isolation;
- cookie name/domain/path/SameSite/Secure shape compatibility using synthetic non-secret placeholders;
- server-rendered request-cookie transmission against a local controlled echo fixture or equivalent non-secret transport test;
- output redaction/allowlist rejection for token-, cookie-, email-, password-, OTP- and link-shaped data;
- process ownership, timeout and exact cleanup;
- three-role context separation and revocation state transition simulation;
- no change to application auth/RLS behavior.

If a preferred browser driver is unavailable, use an equivalent safe rendered mechanism. Tool unavailability alone is not a blocker; inability to meet the genuine session, server agreement, redaction or isolation boundary is.
