# Architect Briefing Spec

`planning/ARCHITECT_BRIEFING.md` is the Builder's sprint-close snapshot for the next Architect session.

It should be short, current, and safe to read quickly. It must not contain source code, secrets, API keys, passwords, tokens, or private credentials.

Required sections and fields, in this order:

1. `## Executive summary` with bold `Business outcome`, `Current focus`, `What is proven`, and `What is not live` fields.
2. `## Readiness signals` with two to four evidence-backed Markdown table rows. Every status is exactly `passed` or `attention`.
3. `## Where things stand` - two to four plain-English sentences.
4. `## Current status` - sprint state and whether the work is complete.
5. `## Since last sprint` - what changed.
6. `## Architecture / file map` - relevant files and responsibilities, no code dumps.
7. `## Decisions` - durable choices made during the sprint.
8. `## Risks / watch-items` - issues to keep visible.
9. `## Open questions for the Architect` - unresolved product or scope choices.
10. `## Evidence` - exact commands or facts and their results, without protected values.
11. `## Plan corrections` - deviations discovered during execution, or `None - the plan held.`
12. `## Validation / test status` beginning with `**Tests:** N passing, N failing.`
13. `## Recommended next Architect action` beginning with bold `Do`, `Owner`, and `Decision` fields.

The briefing reports attention honestly. It must distinguish Preview proof from production proof and must not infer readiness, delivery, or product-wide completion from planning metadata alone.
